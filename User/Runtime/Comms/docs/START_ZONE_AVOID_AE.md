# 03 / 04 / 24 出发区避让 AE

## 视觉判断与握手

出发区识别及其面积占画面 **超过4%** 的条件由MaixCAM判断，MCU不重复计算面积。

- 视觉请求：`F1 F2 AE 1F 2F`。
- MCU完成应答：`E1 E2 AE 1E 2E`。
- 用于03、04、24目标追踪及其丢失恢复，包括E3前进/后退、左右扫视、360°搜索，04的E4搜索、24的EE搜索、07搜索和51补抓搜索；不改变目标类别。
- post22只有已经转为03搜索的分支接受AE；第一次绿色04的E4恢复也可被AE取消。故障、停车、投放、05清点及其E5推散、06搬运和02/42固定推散不接受新的AE动作。
- 发送AE后暂停目标坐标、04/14/34到位事件和E3/E4/EE丢失事件，等待MCU回AE。
- MCU动作中的重复AE合并，不重启、不重新计时。发送失败时保持停车及待回复标志，每100ms自动重试，不依赖视觉重发AE；重复AE也不能推迟重试。
- 收到回AE后，视觉和MCU**统一进入03，以画面中心为误差参考**，用新帧继续当前目标；不再等待被AE取消的13/44/F1，也不恢复旧04/24。无需再次初始化目标类别或发送11/03、51/03。
- 51补抓同样改回03参考点，保留已抓载荷、原补抓次数及原12秒计时。

## MCU动作

1. 停车，取消旧恢复的前后移动、转向和待完成标志；清除旧坐标、PID及旧参考点的到位/丢失事件，不续接旧动作、不发送它的13。
2. 记录当前Yaw，强制向物理逆时针方向旋转180°；利用陀螺仪逐帧累计转角，正确处理跨0°，不使用180°最短路径的任意方向选择。
3. 旋转轮速默认40转/分，剩余20°以内降为20转/分，到位容差沿用4°。
4. 沿用当前全工程的**2秒转向软超时**：超时停止旋转并走完成应答，不进入FAULT，也不会永久等待。日志中的`p`可确认实际已转角度。
5. 按03规则准备**框放下、摄像头广角**，不清载荷。停车回AE，成功后进入普通03或补抓03，等待新鲜且类别匹配的画面中心坐标再驱动车轮，不重新初始化视觉目标锁。

AE不会重置E3/E4/EE恢复次数、目标类别、第一轮绿色限制或补抓次数。
03阶段计时从回包成功重新开始，不恢复旧04/24阶段的已用时间；51补抓的总12秒预算仍连续计时，预算到期仍进入原最终05复检。
保持原有05复检优先级和补抓最终复检要求；补抓的单独06仍不能绕过最终05+ID确认。停止、急停、陀螺仪及电机健康保护可取消AE，取消后不回旧AE。

## 串口输入边界

- AE使用独立请求锁存，不能被随后E3/E4/04等普通事件覆盖。
- 旋转期间UART解析及中断重装一直运行；运动坐标不参与控制，也不能提前打断旋转。
- 进入动作时只隔离旧目标视角的坐标、到位、整理及丢失事件，不无条件清整个邮箱；05/06载荷结果和独立11仍保留。
- 旋转期间的旧坐标或到位半帧，不能在回包后补齐成为新数据。新阶段的05/06/11/AE不随坐标一起丢弃。
- 在回AE**之前**开放新帧入口，回包后不清邮箱；视觉在UART发送期间立即回复的新坐标、04/14/34或05不会被吞。
- 回包成功后、尚未接受新鲜且类别匹配的坐标时重复收到AE，只补回应答，不再次旋转；补回应答失败同样自动重试。
- 记录AE到达时的坐标序号。即使一次旧AE在回包期间到达、随后才收到新坐标，也不能把这次旧AE误判为新避让；新坐标先到、再收到AE才允许下一次180°。
- 动作期间的重复AE和跨回包边界补齐的旧AE半帧直接合并；独立05/06报告和11仍保留。

日志：`[AE] RX ... >03`、`p=... v=...`、`TURN OK`、`TXAE >03`、`REACK`、`TX FAIL RETRY`、`IGNORE`。
参数集中在`User/Config/inc/robot_config.h`的`ROBOT_AE_*`，状态枚举追加，不更改原有状态编号。
回归入口：`tests/verify_supplement_capture.ps1`，覆盖真实解析器、实际状态函数、跨0°/计时回绕、重复与丢包、回包时新坐标/事件、类别及预算/安全保护。
