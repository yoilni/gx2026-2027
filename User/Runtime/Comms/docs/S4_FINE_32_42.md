# 32 / 42 精细整理协议

## 帧与动作

视觉短命令：`F1 F2 CMD 1F 2F`；MCU应答：`E1 E2 CMD 1E 2E`。
坐标仍使用现有11字节有符号误差帧，目标ID过滤保持不变。
MCU在04追踪及14后的整理等待阶段接受32/42；不从05近视角直接启动。
视觉在05需要整理时发送02，MCU执行下文的退车回03流程。04整理入口的02仍执行原推散和12/22握手。

| 视觉命令 | 坐标参考 | MCU动作 | 应答时机 |
| --- | --- | --- | --- |
| 32 | 不使用坐标控制 | 框放下，两轮同速100转/分前进300ms，无坐标PID或航向角环 | 时间到，停车后回32 |
| 42 | ROI中心 | 框放下，X/Y追踪200ms；交替执行下述转弯、前进、反转动作；物资再左转20°，伤员跳过20°，均不后退 | 最后一段转向结束、停车后立即回42 |

32固定前进不等待坐标，不受X/Y误差、到达ROI或航向误差控制；300ms从接受命令时计时，包含原有平滑加速过程，轮速PID保留。重复32不重启计时，动作期间UART接收继续运行。
04整理入口的02及42追踪共用24的ROI像素PID参数：近距离纵向40～70rpm、最大120rpm，旋转限幅25rpm；接近目标、坐标老化均沿用现有减速保护。
200ms从进入像素追踪阶段开始计时；提前到位会停车，仍等待200ms到期。没有有效坐标时停车，即使200ms已到也不进入固定推散；持续500ms没有有效的新目标，转E4恢复，不把未完成的追踪报告成功。
32、42均不进入24抓取、不抬框，不因到达ROI发送或处理34抓取。收到32应答后视觉用新帧继续原14判断，无需额外14命令。

42两次都使用ROI中心误差，不再使用左右侧点。物资路径：

1. 第一次：左转7° → 两轮同速170rpm前进350ms → 快速右转30° → 左转20° → 停车并回42。
2. 第二次：右转7° → 两轮同速170rpm前进350ms → 快速左转30° → 左转20° → 停车并回42。
3. 后续前两次转弯依次交替；新增20°转向始终向左，不随42左右轮次镜像。全部固定动作期间保持框放下，不使用坐标提前打断。

红色伤员任务（当前选择11/ID4）的42起步角度为12°，物资保持7°；伤员省略末尾左转20°，30°反转完成后直接停车并回42；42的左右交替仍正常推进。类别使用当前任务，不使用上次05载荷记录；其他参数和原有E4优先处理不变。

7°以200ms追踪结束时的实际Yaw为基准；30°以350ms前进结束时的实际Yaw为基准；新增左转20°以30°转向结束时的实际Yaw为基准，跨0°正常换算。
若前进没有航向漂移且三次转向均理想到位，第一轮相对追踪结束方向净右转3°，第二轮净左转43°；30°和20°都不是绝对Yaw目标。
起步7°/伤员12°转向使用独立PID：Kp=0.025、Ki=0、Kd=0（误差单位为百分之一度），轮速10～35rpm；7°误差约18rpm，12°约30rpm，误差6°/5°/4.01°时约15/13/10rpm，避免接近目标仍强制30rpm。
30°及最后20°转向仍为30～60rpm，未修改原PID；起步转向也保留原4°到位容差。
每段转向独立沿用2秒软超时，到位无需额外停车确认。
42固定前进段不使用航向角度PID：两轮都给170rpm，不加Yaw差速，也不因航向误差超过10°而暂停前进。
前进170rpm/350ms；电机轮速PID和平滑加减速仍保留，350ms包含加速过程，不代表恒速170rpm巡航350ms。前进起点Yaw仅作日志参考，后续30°目标仍根据前进结束时的实际Yaw计算。
取消末尾后退，物资左转20°结束、伤员30°反转结束即停车应答，不额外等待；06、46等其他阶段的直行角度环保持不变。

32不改变42左右顺序。正常回42后才切换下一轮初始转向；E4取消未回42时保持原方向。
方向交替由MCU内部控制，视觉只需持续提供同一ROI中心参考，不需要发送方向字段或切换侧点。
重新锁定同一目标和E4恢复不重置方向，新任务03/31或新的补抓次数从左转7°开始。
红色起步12°且跳过最后20°；追踪、固定前进和反向30°参数与物资相同，仍只接受当前任务允许类别的新鲜坐标。

## 应答后的判断与三轮上限

正常回32/42后，MCU停车等待视觉的新决定，不主动额外发送14。
视觉使用新帧进入自己的14判断：可继续32/42、改发02推散，或发24抓取。
若视觉确实发来14到位事件，MCU仍按正常协议回14。
三轮上限由视觉计数并改发02；MCU不创建新的“强制推散请求”命令。
动作期间重复32/42不重启动作、不增加次数、不更改方向顺序。

## 丢失及E4

- 32固定前进或04整理入口的02/42追踪期间收到E4：立即停车，进入原E4恢复，不回旧12/32/42。
- 04整理入口的02/42进入固定推散后收到E4：单独锁存，不被随后坐标、14或普通邮箱清理覆盖；完成本类别的固定动作后进入E4恢复，不回旧12/42。
- 存在E4时不再回旧42，42左右序号也不推进。视觉不能继续等待该42应答。
- 进入恢复前隔离旧ROI坐标并清像素PID，先同步04；首次绿色E4按下述共享额度选择强制180°或原360°搜索。
- 同一任务的E4恢复次数及上限保持累计，不因32/42或短暂重新检测到目标清零。
- E4后坐标改用画面中心参考，收到04/44后以新帧恢复关联。

UART解析和接收重装始终运行，动作不使用阻塞延时。
05复检、补抓预算到期、停止及硬件健康故障仍可取消当前动作，不发送被取消动作的旧32/42应答。
原有46避杆协议不变。

## 04整理入口的02：保持原流程

- 普通02：追踪ROI中心200ms → 左转7°（伤员12°）→ 170转/分前进350ms → 右转30° → 物资再左转20°（伤员省略）→ 停车回12，不后退。
- 首次绿色任务的第一次02：追踪ROI中心200ms → 170转/分前进500ms → 用角度环逆时针旋转280°（最高100转/分）→ 停车回12，不后退。转向必须达到累计280°，20秒未完成则安全停车、不回12。
- 回12后等待视觉12或24；收到视觉12时仍直接回22，不做动作。42的方向轮次不变。

## 仅05清点入口的02：退车后直接回03

- 在05清点阶段收到 `F1 F2 02 1F 2F`，PA3张开到74°（伤员抓取68°加6°）。两轮各100转/分直退500ms，不依赖视觉坐标或航向角，不更改PA2挡板。
- 到时停车、闭爪36°、切145°的03视角。MCU发送 `E1 E2 03 1E 2E`，视觉保留原目标类别，直接用新画面发送03参考点误差，不等12、不再发送旧ROI坐标。首次绿色与后续任务动作相同。
- 重复02不重启动作；退出前隔离旧参考点数据，保留回03期间收到的新坐标和事件。05复检、补抓预算、停车及硬件故障仍可取消动作。
- 02不改变42的左右顺序，也不重置目标或补抓预算。其他入口若收到有效12，仍按原逻辑停车回22，不做动作。

## 首次绿色E4 / 05空框E5

首次绿色E4的额度未用时：框保持放下，原地逆时针旋转180°，旋转期间坐标不能打断，不做坐标追踪、不前进也不后退；转完停车回44。
利用陀螺仪累计转角处理跨0°，轮速20转/分、剩余10°以内12转/分；必须累计到180°，不套用2秒转向软到位。20秒仍未完成则安全FAULT停车，不回成功44。

E5动作保持原样：框放下→左转10°→两轮170转/分前进450ms→右转45°→左转20°→停车回44，不后退。
E5的10°角度PID为0.025/0/0、10～35转/分；45°和20°为30～60转/分；每段转向独立2秒软超时，到位无额外停车确认。
E5前进不使用坐标或航向角环，保留轮速PID及平滑加减速；450ms包含加速时间。

- 首次绿色任务的02、32、42成功启动时，每次都计入与E4首次180°恢复共用的额度，当前上限1次。
  05入口的02在成功张爪并启动退车时记录；04整理入口的02和42在进入200ms像素追踪时记录；32在进入固定前进阶段时记录。
  记录的是启动次数，不是完成次数；坐标短暂重现、进入24、AE取消动作不退还或清零。
  动作中重复包、PID周期、42后续固定动作和完成回包不重复计数；放框失败未启动动作不计。
  日志为`[E4-B] cmd=02/32/42 n=已用次数/1`，计数饱和于255，不回绕。
- 额度尚未使用时，首次绿色E4执行一次强制逆时针180°并记1；如果已执行过02/32/42中的任一个，
  下一次E4不再执行180°，而由陀螺仪累计逆时针360°寻找，坐标和有效阶段消息可按原搜索规则打断。
  整圈已完成且仍无新目标时沿用04等待，不重新补推；重获目标后的搜索允许规则保持原样。
- 额度不拦截视觉正常发送的02/32/42，它们继续原动作和握手，并继续累计；仅用于决定E4的恢复路线。
  12仅握手不计数。E5仍不占E4额度，不修改其视觉空框循环规则；07后的红色、31、51任务不计入首次绿色额度。
  计数只在初始化新的绿色21搜索任务时清零；不是掉电保留的历史日志。
- 180°或E5动作期间重复E4不启动第二次搜索，不增加次数；坐标及阶段消息不提前打断，UART解析继续运行。
- E5仍仅在首次绿色05空框流程接受，不消耗或清零E4次数。
- 完成应答为44，不回12/42，不切换42左右顺序；05复检、停止和硬件故障仍可取消动作。E4恢复仍可被AE避让取消，取消后不回旧44；E5不接受AE。

保留四个旧E4日志状态编号：E4强制180°复用`E4_PUSH_RIGHT`，用单独标志分流，不执行旧固定路径。E5的四段依次复用`E4_PUSH_RIGHT`（左10°）、`E4_REVERSE_RIGHT`（前进）、`E4_PUSH_LEFT`（右45°）、`E4_REVERSE_LEFT`（左20°）；名称含REVERSE不代表后退。
07之后红色及黑/绿E4的搜索策略不变。

## 24收到34后的夹爪抓取

当前启用`ROBOT_S4_DIRECT_CAPTURE_AFTER_14`：MCU收到14仍停车回14，等待视觉24；这个等待窗口不执行相邻整理的02/12/32/42，保留E4丢失恢复和原握手超时。MaixCAM需在收到14回包后跳过相邻判断，直接发送24，再发送24参考点的坐标。其他入口的推散动作保留。

进入24时，伤员和物资都用140°广视角，包括31直接抓取和51补抓。追踪及24恢复期间保持该角度，超时回03时使用145°，进入04则恢复140°。05清点近视角为115°。

24入口按类别张开PA3夹爪：绿色/黑色物资64°，红色伤员抓取68°。不再执行旧的双舵机抬框25°，不等待夹爪转到位即进入24追踪；普通24、31黑色直接24及51补抓24一致。PA2保持原位。

收到有效34后退出视觉追踪，物资和伤员均不补进，直接停车，将PA3夹爪设为闭合36°，再用陀螺仪转到当前出发区和红蓝方对应的安全区航向。PA2挡板和PA5镜头不动，夹爪PWM持续输出。

伤员54例外：视觉判定同一伤员物块的高/长 > 1.5 时，先发34，再紧接着发 `F1 F2 54 1F 2F`。MCU在转向完成前独立锁存54，不影响34；转正后张爪到62°，以70转/分直行300ms，停车闭爪到36°，随后按原流程发15/25等待05。不回发54；重复54不重启动作，非伤员、34之前和进入05后的54均不触发补进。转向超时且未对准时不执行54。
07后首块物资闭爪后例外：回34，保留载荷并直接启动51/03补抓，不发15/25。其他抓取（含补抓的第二块）在转正后发15（红方）或25（蓝方），按原流程等待05清点。
普通24、24丢失恢复和补抓的34均使用同一入口；原05复检/补抓预算优先级不变。

## 44后统一接回03（画面中心）

- MaixCAM收到MCU的`E1 E2 44 1E 2E`后直接进入03追踪，用新帧发送画面中心X/Y误差；不再以02/24/E4作为44的唯一回复。
- MCU在发送44前准备03追踪：框保持放下、摄像头广角、清旧PID，隔离旧参考点的坐标、到位和丢失事件及其半帧。只在这个协议边界清理旧运动输入，不清整个邮箱，05/06复检、AE和11独立请求保留。
- 44发送期间的新坐标、E3、04等保留，发送后不清邮箱；不再发送21/03或重置目标锁、E4额度、恢复次数。
- 新鲜ID5画面中心坐标按正常03的X/Y速度和500ms有效期追踪；过期或错误类别先停车，首次绿色任务不换成黑色或发送51。
- 收到E3沿用首次绿色03恢复（前进80转/分800ms，再逆时针360°；新鲜绿色坐标可打断）。收到04进入原04追踪，并回04握手，之后再按14/整理/24抓取流程继续。
- 不再停在旧的“44后等02/24/E4”状态，也不触发该旧等待的5秒超时。14应答后原有5秒整理等待不变。
- E4的180°完成和E5的推散完成均使用上述44→03入口；已用额度的360°搜索仍走原04恢复入口，不新增44。
