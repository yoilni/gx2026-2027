# 06安全区黑杆避让46

本协议只负责MCU动作和握手；面积50%及黑杆相对位置由MaixCAM判断。
MCU不重复进行视觉验证，也不把46当作26最终投放。

## 视觉决策

- 物资：黑杆偏右可发26；偏左发46。
- 伤员：黑杆偏左可发26；偏右发46。
- 发46后暂停运动坐标和26，每500ms重发46，直到收到MCU应答。
- 收到应答后使用新帧继续找安全区；本轮不再检查黑杆，面积再次达到50%直接发26。

请求：`F1 F2 46 1F 2F`。
完成应答：`E1 E2 46 1E 2E`。

## MCU动作

使用05确认并保留的实际载荷类别，不使用安全区坐标ID判断伤员/物资：
ID4为伤员；ID3/5/6为物资。

1. 停止旧追踪/6E/36等接近动作，先转到按启动零点、出发区和红蓝方换算的安全区绝对方向。
2. 保持该安全区航向，以150转/分后退800ms；800ms从初次转向结束后开始，不包含转向时间。
3. 相对安全区航向，物资左转90°、伤员右转90°，不再以46接收时尚未对正的车头方向计算。
4. 保持侧向航向，以150转/分前进600ms。
5. 转回按启动零点、出发区和红蓝方换算的安全区绝对方向。
6. 停车，回发46，然后用新安全区坐标恢复原06视觉追踪；不强制再等一次16。
   新26按统一入口检查当前角落撤离范围；不需撤离时进入最终对正和投放流程。

框保持放下、MG90保持广角，不额外抬框或切近视角。
速度和时间集中在`User/Config/inc/robot_config.h`的`ROBOT_S6_BAR_*`。
转向角度PID10～40转/分，无额外到位等待；每段定点转向保留2秒软超时继续。
前后直行的角度修正上限±10转/分，单轮限幅160转/分，避免150转/分被旧110限幅截断。
距离为定时轮速目标，并非里程定位，需按实车表现调整。

## 去重与恢复

- 仅06搜索、追踪、6E、普通侧移、36及追踪超时后退阶段可开始46。
  05清点、03/04/24、角落撤离和已经开始26投放时的新46不启动路线。
- 46使用独立接收锁存，不被后到16/26覆盖；动作中重复46不重置阶段、航向或计时。
- 动作中运动坐标和26不参与控制；仅隔离旧坐标/26，UART解析和接收中断始终运行。
- 动作结束后再次收到46，只补回应答，不重做路线，也不清除新的坐标/26。
  完成标记在本次06载荷会话中保留，新载荷进入06时重置。
- 首次回46前清理旧运动参考，发送前开放新帧入口，发送后不清邮箱。
  因此视觉在应答发送期间立即回复的坐标、26或05不会被清掉。
- 应答发送结束后使用统一的新时刻建立追踪计时，后续状态处理刷新时刻和坐标年龄。
  即使UART发送跨过毫秒，也不能把旧周期时刻减去新起点误判为超时进入FAULT。
  旧时刻调用仅暂停该次处理，不清除待处理事件；无新坐标满1秒仍按原流程进入6E。
  实际15秒接近超时保护保持不变，不新增E6或6E串口命令。
- 应答发送失败时保持停车、保留动作已完成标记，等待下一次46重试应答；不重复走路线。
- 05复检仍可中止46，ID报告和结果按原协议处理；停止、急停、陀螺仪及电机故障保护不变。

日志：`[46] START`、`[46] ST=...`、`DONE TX46`、`DUP KEEP`、`REACK`、`ACK FAIL WAIT46`。
角度日志角色为`46_BACK`、`46_SIDE`和`46_SAFE`。
初次对正与最终返回安全区方向复用`46_SAFE`状态编号，通过内部阶段标记区分；初次转完打印`[46] SAFE >BACK`，不会提前回46。
回归入口：`tests/verify_s6_corner.ps1`，用真实串口解析器和状态函数验证方向、时序、重复包及安全保护。
交接计时覆盖发送耗时0/1/2/20/80ms、系统计数回绕、新ID1坐标与16、26/05优先处理及999/1000ms丢失边界。
