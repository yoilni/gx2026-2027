# HWT101接入

协议来源：[维特HWT101官方协议](https://wit-motion.yuque.com/wumwnr/ltst03/seuiba)。

## 接线与波特率

- HWT101 TX → STM32 PC11（UART4 RX）。
- HWT101 RX → STM32 PC10（UART4 TX），必须接，否则无法发送置零指令。
- 两端共地，使用TTL模块，不将RS232/RS485电平直接接到MCU。
- UART4和模块自身均设为115200、8N1；UART2（PD5 TX/PD6 RX）继续作为
  115200调试接口，无线烧录器/串口助手按ASCII显示。
- 官方协议BAUD寄存器默认值是9600。如果模块还在9600，先用厂商上位机
  将模块设置并保存为115200。MCU不会盲发旧波特率配置或改动其他串口。

## 上电流程

`HWT101_Init(&huart4)`启动单字节中断接收。独立的`hwt101Task`每20ms调用
`HWT101_Service()`，执行一次上电归零：

1. 从接收初始化开始等待500ms，为模块启动留时间。
2. 发送解锁`FF AA 69 88 B5`，等待200ms。
3. 发送Z轴角度归零`FF AA 76 00 00`，等待500ms。
4. 发送保存`FF AA 00 00 00`，等待200ms。
5. 清除归零期间旧角度及半帧，只接受之后完整收到的新角度帧。

这不是20秒的自动零偏校准，不发送`FF AA 48 01 00`。
等待以状态机实现，不调用阻塞延时；仅5字节UART发送有20ms的HAL超时。
归零期间LED、视觉接收、串口调试及RTOS继续运行，车轮不能使用未准备好的Yaw。
初次测试保持车静止，上电约1.4秒后看到新Yaw再按PE12启动。
重复初始化返回HAL_BUSY，避免在运动中突然归零。
任一归零命令发送失败则保持INIT_FAILED，不执行后续保存、不提供有效角度。
UART错误恢复只重启接收，不再次归零。

发送成功仅表示MCU UART传输完成，不等于传感器确认；协议没有为这三个
命令定义独立ACK。现场需要确认归零后静止Yaw接近0°。

## 解析与输出

角度帧：`55 53 00 00 00 00 YawL YawH VL VH SUM`。
低字节在前，有符号16位角度乘`180/32768`；内部保存百分之一度的整数。
SUM为前10字节和的低8位，校验失败不更新角度或时间戳。
`55 52`角速度及其他合法数据帧不当成Yaw。
串口错误、断帧和噪声后自动重新寻找帧头，不在中断中打印。

每750ms经现有DebugUart队列向UART2发送一条`[HWT101]`记录：

```text
[HWT101] TX FF AA 76 00 00 hal=0
[HWT101] ZERO/SAVE SENT, WAIT FRESH YAW (NO SENSOR ACK)
[HWT101] yaw=359.50 seq=10 age=5ms version=0000
[HWT101] state=5 NO FRESH YAW rx=1 crc_err=0 uart_err=0
```

打印Yaw使用0～359.99°显示，内部仍为带符号角度，保持现有角度环的
跨零算法与PE12场地零点。接收层500ms过期，比赛角度环保留150ms新鲜度保护。
Mission和OLED已切换到HWT101，新旧驱动不会同时占用UART4。
旧JY901S目录保留但不再参与编译。安装后先架空验证左转Yaw增长、右转Yaw减小；
安装方向改变时不能直接假定原来的转向符号仍然正确。

## 验证

`tests/verify_hwt101.ps1`编译实际驱动并验证归零时序、校验、符号、跨零、
坏帧重同步、旧半帧隔离、过期、UART接收恢复及发送失败。
主机回归不能验证真实模块是否接收命令，也不能替代电气接线和实车测试。
