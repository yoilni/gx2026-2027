# gx_version1

基于 STM32F407ZGT6 和 STM32 HAL 库的 M2006 电机 CAN 控制实验工程。

## 当前功能

- 使用 CAN1 与大疆 M2006 电调通信。
- CAN1 使用 PB8（RX）和 PB9（TX），总线速率为 1 Mbps。
- 接收电机 1–4 的反馈帧（CAN ID `0x201`–`0x204`）。
- 向 CAN ID `0x200` 发送四路电机电流控制指令。
- CAN 硬件过滤器仅接收 `0x201`–`0x204`，并启用自动重发和总线关闭自动恢复。
- 任一电机反馈超过 100 ms 未更新时，该路立即输出零电流并清空 PID 状态。
- 左右速度接口按电机 1/4 为左侧、2/3 为右侧映射；制动时四路同步切换目标和电流上限。
- 使用 FreeRTOS 高优先级任务，每 2 ms 执行一次 M2006 速度环 PID 控制。
- 使用 FreeRTOS 低优先级任务，每 200 ms 刷新一次 JY901S 姿态 OLED 显示。
- JY901S 姿态超过 500 ms 未更新时，OLED 显示 `OFFLINE`，恢复通信后自动恢复角度显示。
- 默认任务每 500 ms 翻转一次 PC13 LED（完整闪烁周期为 1 秒）。

## 当前电机设置

启动目标在 `Core/Src/main.c` 中设置：

```c
SpeedLoop_SetMotorTarget(4U, 0.0f, 1000);
```

参数依次为：`电机编号（1–4）`、`减速箱输出轴目标转速（rpm）`、`最大控制电流`。

当前设置为电机 4 停止。若需让电机 1 以 10 rpm 转动，可修改为：

```c
SpeedLoop_SetMotorTarget(1U, 10.0f, 1000);
```

## 接线与使用注意

- MCU 的 PB8/PB9 不能直接连接 CANH/CANL，必须经 CAN 收发器连接。
- CAN 总线两端应配置 120 Ω 终端电阻。
- M2006 电调需要独立、可靠的电源供应。
- 下载/复位 MCU 时，程序停止发送 CAN 电流指令；如需避免下载瞬间的意外动作，建议在硬件上使用 CAN 收发器的 `EN`/`STB` 引脚实现默认静默。

## 构建

使用项目的 CMake 配置构建：

```powershell
cmake --build cmake-build-stm32 --parallel 4
```

生成的固件为 `cmake-build-stm32/gx_version1.elf`。

## FreeRTOS 任务文件结构

- `Core/Src/freertos.c` 仅保存任务属性、句柄和创建逻辑。
- `OLED/oled_task.c` 定义 OLED 初始化、显示逻辑和 OLED 任务入口。
- `M2006/M2006_task.c` 定义 2 ms 电机控制任务入口。
- `Core/Src/led_task.c` 定义状态灯任务入口。
- 各 `_task.h` 使用外部声明，将任务入口提供给 `freertos.c`。

### 2026-09-24 — MaixCam 坐标帧升级为 11 字节有符号误差

- 比赛配置拨码调整为：PE13高电平选红方、低电平选蓝方；PE14为高位、PE15为低位选择出发区，编码`01/10/11/00`分别对应出发区`1/2/3/4`。PE12仍为低电平启动按钮，启动时锁存阵营和出发区。状态1按出发区1/4左转、2/3右转。
- 启动时同时记录场地安全区正向航向：出发区1/2以初始0°指向蓝方、180°指向红方；出发区3/4以初始0°指向红方、180°指向蓝方。状态6收到26后使用该航向把车身转正，再执行最终推进。
- USART3 坐标帧改为 `F1 F2 CLASS XH XL XS YH YL YS 1F 2F`。
- X、Y 使用高字节在前的幅值编码；`01` 为正，`02` 为负。
- 状态2转向完成后以110 rpm直行3.0秒越过减速带，并用JY901S航向P环保持转向完成时的±45°目标方向；四个出发区共用相同闭环行驶时间，目标航向由各自出发区决定。根据20:31日志，航向误差曾达到约22°且原20 rpm修正长期饱和，因此P增益提高到0.025、最大修正提高到35 rpm；修正仍只降低内侧轮，保证单轮不超过110 rpm。停车稳定0.3秒后再进入状态3，避免车身振动干扰视觉PID。
- 进入状态3时先放下收纳框并等待1秒稳定，MG90保持80°广视角；随后发送 `E1 E2 12 1E 2E` 选择绿色，再发送 `E1 E2 03 1E 2E` 开始搜索，以 `xerr=0` 为目标进行原地 PID 对准。进入视觉03后连续2秒未收到绿色误差时，以减速带航向为基准用JY901S先顺时针转90°、再逆时针转180°；扫动中一旦收到坐标立即停止扫动并恢复视觉PID。若已识别目标但随后连续丢失2秒，会重新允许一次扫动，而不会永久停车等待。逆时针180°内部使用两个连续90°航向点，避免180°最短路径方向不确定。
- 横向对准后保持03模式，使用x误差差速转向、y误差控制前后速度；左右单轮目标均按比例限制在100 rpm以内。
- 收到 MaixCam 的 `F1 F2 04 1F 2F` 后停止原03追踪；此时收纳框已经处于放下状态，不再重复动作或等待，直接使用MaixCam的新坐标追踪物块到画面中心。MG90在04、14、02、12、24和34整理流程中始终保持80°广视角。收到`F1 F2 14 1F 2F`后以60 rpm持续前进1秒，只用X误差修正方向，转向修正限幅±20 rpm；随后回发`E1 E2 14 1E 2E`握手并等待02。
- 收到`F1 F2 02 1F 2F`进入整理模式：第一次以约60 rpm固定向右弧线推进1.5秒，左右轮目标为71/50 rpm（差速21 rpm），再以50 rpm后退700 ms并发送`E1 E2 12 1E 2E`。通常收到MaixCam回发的`F1 F2 12 1F 2F`后，第二次以约60 rpm固定向左弧线推进1.5秒，左右轮目标为50/71 rpm，再以50 rpm后退700 ms。两次弧线推进不再叠加视觉X/Y修正；收到14后的1秒推进仍保留X误差修正。进入02后，MaixCam也可随时发送`F1 F2 24 1F 2F`跳过剩余整理；STM32会立即停车、抬框并直接进入最终24目标的XY追踪，不再等待12，也不重复发送24命令。为避免02与24连续发送时事件槽被覆盖，在等待02的位置直接收到24也按跳过处理。
- 第二次整理完成后抬框并等待1秒，发送`E1 E2 24 1E 2E`；在24模式下按“目标物块到框中点”的XY误差继续追踪。如果24模式由MaixCam的跳过事件触发，则只抬框并开始追踪，不回发24。24模式连续2秒没有有效坐标（MaixCam每500 ms发送EE会令旧目标失效）时，STM32以50 rpm后退700 ms，强制左转到陀螺仪绝对270°，再由角度环转到绝对90°并恢复24等待；仍无坐标可重复恢复。后退或转向期间一旦重新收到坐标，会立即停车并恢复24追踪。收到`F1 F2 34 1F 2F`后先以60 rpm直行150 ms，使物块进一步进入框内，再停车放下框并等待1秒；随后按已锁存阵营发送`E1 E2 15 1E 2E`（PE13高电平，红色安全区）或`E1 E2 25 1E 2E`（PE13低电平，蓝色安全区），然后进入状态5检查。02、04、05、06、12、14、16、24、26、34为MaixCam发给STM32的事件；12、14、15、24、25为本流程中STM32可发送的命令，其中24根据帧头区分方向。
- 状态5收到`F1 F2 05 1F 2F`后把MG90从80°广角转到45°近视角，等待MaixCam判断框内物块。如果收到`F1 F2 02 1F 2F`，MG90立即回到80°广角，底盘先使用JY901S角度环按最小角度转到由阵营和出发区锁存的安全区正向航向；稳定后抬框并等待1秒，以50 rpm保持该航向后退700 ms，停车放框并等待1秒，再进入已有的右推、左推及24最终追踪整理流程。整理完成后会再次放框、发送15/25并进入状态5复查。如果无需整理而收到`F1 F2 06 1F 2F`，MG90同样先回到80°广角，再进入状态6寻找安全区。UART2每500 ms输出当前等待05还是02/06以及MG90视角，并在整理前对正、后退期间输出目标航向、误差和车轮指令。物理复位后UART2会立即及延迟500 ms输出启动标记和`POWER_ON/BROWNOUT/IWDG`等复位原因。
- 进入状态6时MG90保持80°广角。由于启动时已经按阵营和出发区锁存安全区正向航向，底盘先由JY901S按最小角度路径转向该航向，转向上限30 rpm。到达该方向后连续2秒未收到`F1 F2 16 1F 2F`，启动视觉恢复动作：前两轮以40 rpm航向闭环前进500 ms，第三轮及之后提高为70 rpm前进2000 ms；随后使用JY901S角度环PID，以当前方向为基准先左转45°，再从左转位置右转90°，最终朝基准方向右侧45°。动作任意阶段收到16都会立即停车、清除旧坐标并进入安全区视觉追踪；一轮仍未发现则等待2秒后可再次执行。搜索全过程仍受20秒总超时保护。
- 收到16后先比较当前陀螺仪角度与已锁存的安全区正向航向。以出发区4蓝方为例，安全区航向为180°：当前处于`[90°,180°]`时直接进入原二维视觉PID；处于`(180°,270°]`时先用JY901S转到270°，以50 rpm航向闭环前进700 ms，再使用安全区X误差原地转向对准。X误差进入±15像素并稳定300 ms后重新检查陀螺仪角度；若仍处于`(180°,270°]`则重复侧向移动，进入`[90°,180°]`后才切换到原二维视觉PID。其他阵营和出发区使用相对于各自安全区航向的同等±90°关系。整个侧移循环和后续追踪共用15秒总超时。
- 原二维视觉PID使用X误差控制转向、Y误差控制前进速度，前进限幅60 rpm、转向限幅35 rpm、车轮合成限幅80 rpm。追踪中连续2秒没有新坐标时，执行“前进、角度环PID左转45°、再右转90°”恢复动作；动作中坐标恢复即停车并继续PID。MaixCam判断安全区面积超过50%后发送`F1 F2 26 1F 2F`；STM32停止视觉PID，根据阵营和出发区锁存的安全区正向航向用JY901S转正，先以80 rpm保持该航向倒车500 ms并制动200 ms，再以70 rpm航向闭环推进1300 ms。物块推进安全区后停车、抬起收纳框并等待1秒，然后以70 rpm保持原航向完成最后的倒车2000 ms，再用JY901S旋转180°并停车进入`S6_SAFE_ZONE_REACHED`。最终推进和退出倒车车轮合成限幅均为80 rpm。收纳框放下标定更新为左219°、右2°。
- 根据20:55日志，S6小角度回正时5 rpm无法克服底盘静摩擦，角度环最小转向速度已提高到10 rpm；本次06定向搜索的最大转向速度提高到30 rpm，PID增益保持不变。
- 同时识别 `F1 F2 EVENT 1F 2F` 短事件帧；收到 `EE` 后立即令旧目标失效并停车。

### 2026-09-14 — 新增 MaixCam 物块数据接收与 OLED 显示

- 使用 USART3（PD8/PD9，115200、8N1）接收 MaixCam 数据。
- 新增逐字节中断接收、状态机解析和 9 字节帧缓冲区。
- 帧格式为 `AA BB ID X_H X_L Y_H Y_L CC DD`，帧头和帧尾均使用宏定义。

- OLED 改为显示 MaixCam 在线状态、物块 ID、X 坐标和 Y 坐标。

### 2026-08-31 — 外设任务实现模块化

- `freertos.c` 只负责配置和创建任务，具体任务入口移动到各自的 `_task.c`。
- OLED 初始化、姿态格式化以及在线/离线显示从 `main.c` 移至 `OLED/oled_task.c`。
- M2006 周期控制和 LED 周期任务分别移至 `M2006/M2006_task.c` 与 `Core/Src/led_task.c`。
- JY901S UART HAL 回调从 `main.c` 移至 JY901S 模块。
- `main.c` 仅保留系统初始化、外设模块初始化和调度器启动流程。

### 2026-08-31 — 加强 CAN 总线与电机失联保护

- 启用 CAN 自动重发和总线关闭自动恢复，并同步更新 CubeMX 配置。
- 将接收过滤器限制为四路 M2006 反馈 ID `0x201`–`0x204`。

- 首帧反馈自动建立角度零点，避免上电角度跨圈误判。
