# 06侧移与角落撤离

角落撤离同时应用于物资ID3/5/6（含51任务按物资推断）和伤员ID4。
两类载荷共用撤离范围和动作；普通侧移仍按物资/伤员分别判断，撤离优先。
类别沿用05确认、进入06时冻结的搬运类别，不以安全区坐标ID判断。

## 出发区/红蓝方范围

以下θ均相对PE12启动时锁定的陀螺仪零点，不是传感器原始yaw。

| 组合 | 安全区方向 | 物资普通侧移触发范围 → 横向方向 | 物资/伤员共用角落撤离触发范围 → 横向方向 |
|---|---|---|---|
| 1/2区红方，3/4区蓝方 | 180° | 135° ≤ θ ≤ 157° → 90°；190° < θ ≤ 224° → 270° | 90° ≤ θ < 135° → 90°；224° < θ ≤ 270° → 270° |
| 1/2区蓝方，3/4区红方 | 0° | 315° ≤ θ ≤ 337° → 270°；10° < θ ≤ 44° → 90° | 270° ≤ θ < 315° → 270°；44° < θ ≤ 90° → 90° |

共享边界135°/224°及其对称角315°/44°不触发撤离；普通侧移是否触发按载荷类别判断。
其它边界的包含/排除情况按表执行；范围外仍按原06视觉XY追踪。
伤员保留原侧移区间，并增加第二侧区间，撤离仍优先。伤员实际普通侧移范围为：

- 1/2区红方、3/4区蓝方（安全区180°）：135° ≤ θ ≤ 165° → 90°；190° < θ ≤ 224° → 270°。
- 1/2区蓝方、3/4区红方（安全区0°）：315° ≤ θ ≤ 345° → 270°；10° < θ ≤ 44° → 90°。

伤员在224°/44°触发普通侧移，超过该边界才进入角落撤离；190°/10°不触发第二侧侧移。

## 入口与动作

- 收到06后首次按最短角度转向安全区：旋转上限85转/分（本次65→85），
  仍由角度PID随误差减速；不修改36绕障、普通侧移、6E恢复和26最终对正的速度。
- 沿用06收到16后视觉XY追踪、累计有效追踪满500ms再判角度的入口；每次侧移返回重新累计。
  X是否已经对准不影响该角度判断；短暂断帧只暂停累计时间，长期丢失仍走原恢复。
- 角落撤离与普通侧移仍由MCU本地的角度/载荷规则选择，不需要视觉另发触发命令。
  36绕障返回后的保存角度判断也使用同一选择入口。
- 安全区X未确认对准时，Y追踪仍限速30转/分；X确认对准后纵向目标范围为100～150转/分。
  坐标过期减速及最终26投放参数保持不变。
- 普通侧移：转横向方向 → 120转/分按角度计算时长前进 → 转安全区方向。
  以原100转/分×490ms为1倍名义路程；有效普通侧移区间中，靠近安全区正方向的边界为1倍，
  远离安全区正方向的边界为3倍，中间线性插值。当前时长约408～1225ms。
  3区蓝方物资第一侧：157°为1倍/408ms，146°为2倍/817ms，135°为3倍/1225ms；
  第二侧：190°附近为1倍，224°为3倍。其它出发区、红蓝方对称换算。
  伤员在实际普通侧移区间135°～165°（或315°～345°）内同样由远到近3倍→1倍；
  新增第二侧区间190°～224°（或10°～44°）沿用物资第二侧的1倍→3倍线性路程。
  时长在触发瞬间按判定角度冻结，转到90°/270°后不重新计算；36返回后的保存角度也适用。
  普通侧移轮速限幅130转/分，角落撤离仍为110。路程比例为速度×时间的名义比例，
  实车仍受速度平滑及打滑影响；串口`[S6-P-DIST]`打印角度、速度、时长和路程百分比。
- 角落撤离依次执行：
  1. 转到安全区反方向（安全区绝对目标+180°）。
  2. 100转/分前进2000ms。
  3. 转到触发范围对应的90°或270°方向。
  4. 100转/分前进1200ms。
  5. 转回安全区方向，停车、保持完全放框，向视觉发送一次05，收到05回包后切近视角复查载荷。
- 三段旋转沿用侧移角度环，上限55转/分；两段前进也使用角度环保持各自目标方向，
  轮速限幅110转/分，沿用已有速度平滑。撤离动作期间保持完全放框、广视角；05回包后才切近视角。
- 复查合格后直接恢复16阶段追踪，不要求视觉再发16。记录当前载荷的撤离已完成，
  即使后续追踪、6E恢复或36返回后的判角度又落入撤离范围，也不重复该撤离动作。
  普通侧移仍可按新载荷类别及角度判断；复检后02整理不清撤离标记，
  空框24重新抓取或下一轮07新任务才重新允许撤离。
- 动作不因途中普通坐标或26而中断。撤离期间收到26只计数、打印并丢弃，
  不缓存，不在撤离结束后补执行投放；在撤离中开始、返回后才解析完整的旧帧也丢弃。
  返回后先完成05载荷复查，恢复安全区追踪后必须收到新的26才进入原最终对正投放。
  视觉端需继续提供安全区坐标，并允许重新满足投放条件后发送新26，不能只发一次后停止。
  普通追踪/侧移/恢复阶段仍保留26优先的既有规则。
- UART接收解析持续运行；状态机不使用阻塞延时。角落动作整体仍有15秒故障超时；
  单段定点转向达到2秒上限后停车并继续下一步，打印真实角度，不修改陀螺仪数值或虚报到位。电机/陀螺仪异常、停止和急停仍停车。

## 撤离后的05复查握手

只在角落撤离最后转回安全区后触发；普通侧移、36绕障、6E扫描不增加此握手。

1. MCU停车、完全放框、暂时保持广视角，发送一次 `E1 E2 05 1E 2E`。
2. MaixCAM只在06处理该请求，回 `F1 F2 05 1F 2F`。MCU收到回包后停车、切近视角，
   进入清点等待状态，非阻塞等待镜头稳定500ms。视觉暂停安全区坐标、26、36，
   回包发送成功后等500ms再连续确认3帧；连续帧验证由视觉完成，MCU不重复验证。
   RX05为独立锁存，后面紧跟ID/06也不会覆盖握手；重复05不重启计时或清除报告。
3. 视觉按本次新画面决定结果：
   - 载荷合格：先发11字节零误差载荷ID报告，间隔50ms再发 `F1 F2 06 1F 2F`。
   - 有物块但需要整理：发 `F1 F2 02 1F 2F`，复用原05→02转正、后退、整理流程。
   - 空框或无合格载荷：发 `F1 F2 24 1F 2F`，复用原24抬到20°、追踪抓取流程。
4. 载荷ID沿用3/4/5/6；绿黑混装报告ID5，X/Y必须均为零。报告只用于类别确认，不驱动车轮。
   收到06时冻结它之前500ms内的新报告；没有报告、报告过期或第一次绿色任务报告不是ID5时，
   保持停车，等待新的ID+06或02/24。不能用此前搬运的旧ID代替本次确认。
5. 合格06后保持完全放框、立即切回广视角，停车等待800ms，随后直接恢复安全区XY追踪，
   不重走“旋转找安全区/等待16”入口，也不重置16阶段累计8秒追踪时间。
   视觉同样等待800ms后恢复新帧输出；新安全区坐标不会在恢复边界被清除。
   复查中的旧26丢弃；06之后恢复边界到达的新26先锁存，800ms镜头等待结束后才执行投放。
   没有新坐标时先保持停车，从800ms等待结束起再累计原1秒丢失计时，不会立即触发6E。

复查是独立状态（92等待05回包、93为所有入口共用的清点结果等待、94广角恢复800ms），
不会发送51/03、新建51补抓预算或触发E5动作；视觉也不累计此流程的E5循环次数。
05回包之前的02/24/06与坐标均不能触发动作；无回包时保持停车并每500ms打印等待信息。
发送05失败或舵机/电机/陀螺仪故障仍进入FAULT；停止、复位和离开复查状态会关闭接收窗口。
UART2的 `[LOAD05]`和`[S6-CHECK]` 打印入口、确认/拒绝ID及下一步处理。
普通05、补抓、整理及恢复也接视觉主动05最终复检，完整协议见[最终载荷复检](FINAL_LOAD_RECHECK.md)。

UART2日志：`[S6-C]`打印载荷ID、出发区/红蓝方、触发角度、两段目标角度和阶段；
`[ANGLE-T]`标识`CORNER_AWAY`、`CORNER_SIDE`，安全区方向为`SAFE_HOLD`。
配置入口位于`Task/robot_config.h`的`ROBOT_S6_CORNER_*`和`ROBOT_S6_SIDE_RULE_ROWS`。

## 验证

`tests/verify_s6_corner.ps1 -Compiler <gcc路径>`使用实际UART解析、类别选择、
角度表、追踪计时、像素PID、角度PID和角落状态函数，模拟HAL及轮速输出。
覆盖8种组合、物资/伤员分类、百分之一度边界、非零零点、两个撤离路径、旧坐标清理、
36返回后判断、各撤离阶段忽略26/旧半帧、撤离后05握手、复查后新26正常投放、故障/超时/停止
及逐字节接收连续性。
仿真不代替实车路程、角落碰撞余量和框内物块保留情况的验证。

`tests/verify_supplement_capture.ps1`还覆盖复查05/ID/06同批到达、重复握手、06优先、
报告缺失/过期、首次绿色类别限制、02/24分流、旧半帧清理及接收连续性，
以及800ms恢复边界新坐标/26保留、无需新16、同一载荷不重复撤离及新载荷重新启用撤离。
