# 05框内确认与06搬运类别

06侧方横移按搬运物块类别选择既有的出发区/红蓝方角度表，
不再仅凭最初搜索命令判断。红色ID4是伤员，浅蓝ID3、绿色ID5、黑色ID6是物资。
51任务仅找黑色/绿色；没有05类别信息时也按物资处理，不继承上一轮伤员类别。

## 视觉端类别上报

5字节的05、06事件不带物块类别，单独发送它们无法让MCU知道05实际确认的颜色。
不需要新包头、校验或新命令：可沿用11字节帧的ID字段上报框内确认结果。

1. 发05请求MCU将摄像头切到近视角。
2. 用新画面确认框内物块，按现有11字节帧发送该物块ID。
   此阶段ID必须代表框内确认的物块，不是画面外侧任意目标。
   X/Y可填零，因为MCU在05只记录类别，不运行坐标PID。
3. 无需整理时发送06。MCU先记录05类别，再切广角、找安全区。
   需要整理时仍按原协议发02，整理完成后的下一次05重新确认。

例如绿色确认帧（X/Y均为0、符号均为01）：

`F1 F2 05 00 00 01 00 00 01 1F 2F`

黑色将ID字段改为06，红色改为04，浅蓝改为03。
这些是11字节类别/坐标帧，不是5字节同值事件。
确认帧必须在本次05请求之后到达，并在500ms内被MCU读取。

## MCU记录规则

- 首轮进入07之前，03/04/24及其目标搜索只接受ID5作为追踪坐标；
  02/12整理的非目标物块坐标和06安全区坐标不受这个目标类别过滤影响。
- 首轮05必须先收到本轮近视角确认窗口内的新鲜ID5帧，之后收到06才进入搬运。
  仅发送05/06而没有类别确认，或最新确认ID为3/4/6时，MCU停车留在05，
  UART2打印`[S5-GREEN] RX06 BLOCKED`。重复05不会清空本窗口已确认的类别。
  视觉可发02继续整理或24重新抓取；若后来确认绿色，需发送新ID5帧并再次发送06。
  被拒绝的06不延后自动执行，也没有新增拒绝握手命令。
- 首轮ID5必须代表满足绿色抓取条件的框内确认，不能用“绿色+黑色都是物资”
  的汇总ID5冒充单一绿色确认。MCU只有ID，无法从汇总ID5判断框内是否混有黑色。
  07之后仍保留绿色/黑色混合物资上报ID5的原约定。
- 每次进入05先清理上一轮类别，按本轮任务及最后有效黑/绿ID建立默认值。
- 优先采用05阶段的新鲜ID3/4/5/6。旧帧、过期帧和安全区ID1/2不覆盖类别。
- 进入06后冻结类别，安全区坐标只用于追踪，不改变伤员/物资分类。
- 07之后未收到类别帧时仍保留本轮任务推断，日志显示`source=TASK_FALLBACK`，
  不声称视觉已确认；首轮绿色不允许靠这个推断直接进入06。
- 收到确认帧后显示`[S5-CARGO] CONFIRMED`；进入06显示`[S6-CARGO] LOCK`。
- 侧移日志`[S6-P]`同时打印`target`搜索命令、`cargo`搬运ID和`kind`。
- 本次修改不改变侧移角度表、1秒视觉追踪后判角度、26直接对正推进等动作。

## 首轮绿色05空框循环：E5

MaixCAM负责累计“05空框 → 24重新抓取 → 再次进入05仍空框”的循环次数。
达到视觉端约定的两次循环后，仅在首次绿色任务的05阶段发送一次：

`F1 F2 E5 1F 2F`

- MCU仅在05、尚未进入07且当前搜索命令为21（绿色）时执行E5。
  07之后的05忽略E5，即使当时正在找绿色，也不会触发此动作。
  接收层在其他阶段拒绝E5，不覆盖已有的02/24等事件；任务统一打印
  `[S5-E5] IGNORE`、忽略数量及当前状态/任务，动作期间重复E5也按此规则记录。
- 摄像头切广视角，保持框放下，清除本轮05类别确认，完整执行与绿色E4
  相同参数的“右推 → 后退 → 左推 → 后退”。收到坐标不会打断这四段动作；
  动作期间重复E5也不会重新开始或延长计时。
- 动作结束发送 `E1 E2 44 1E 2E`，进入原有等待02/24/E4状态（5秒握手超时）。
  紧邻发送44之前原子清除旧坐标、旧事件（包括独立缓存的11/26）并重置PID；
  尚未解析完整的旧帧允许解析完后丢弃，避免44之后重新发布旧输入。
  不停止或重启UART接收，不用阻塞延时执行动作，44之后的新02/24回复不再被清除。
  MaixCAM等待44后再继续判断并发送02整理或24重新抓取，不应在推散途中提前发这些事件。
- E5只复用E4的路径和44握手，不消耗也不重置E4原有两轮推散额度；
  即使先前E4额度已用完，本次有效E5仍执行完整推散，不变成360°搜索。
- MCU不自行累计“空框循环”，也不自动重发E5；视觉应在收到44后完成本次请求、
  更新其循环计数，下一次确需E5时仍在05发送。05收到E4的原有等待行为保持不变。
